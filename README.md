# SupportBot — Telegram Order & Helpdesk Demo

Демонстрационный Telegram-бот для приёма заказов и обработки обращений клиентов. \
Позволяет пройти полный цикл работы: от выбора услуги и создания заказа до технической поддержки, закрытия обращения и получения отзыва.
## Возможности демо

### Клиент

1. Выбор языка интерфейса: русский или английский.
2. Просмотр каталога доступных услуг.
3. Создание заказа с описанием задачи.
4. Просмотр списка своих заказов и текущих статусов.
5. Создание обращения по конкретному заказу или отдельного тикета.
6. Выбор категории обращения: вопрос, ошибка или техническая поддержка.
7. Отправка сообщений и файлов в рамках обращения.
8. Просмотр истории переписки.
9. Оставление отзыва после закрытия тикета.

### Сотрудник

1. Просмотр заказов и очереди обращений своего Workspace.
2. Изменение статусов и приоритетов заказов.
3. Изменение статусов и приоритетов тикетов.
4. Ответы на обращения клиентов.
5. Добавление внутренних заметок к заказам и тикетам.
6. Просмотр истории внутренних заметок.

Внутренние заметки отделены от публичной переписки и доступны только в роли сотрудника.

### Жизненный цикл заказа

`new → clarification → accepted → in_progress → review → completed`

Также предусмотрена отмена заказа.

### Жизненный цикл тикета

`new → in_progress → waiting_client → resolved → closed`

## Демонстрационный режим

Каждый пользователь получает собственный изолированный Workspace.

Внутри него можно переключаться между ролями клиента и сотрудника, проходя полный сценарий обработки заказа и обращения с одного Telegram-аккаунта.

Данные разных Workspace изолированы. Демонстрационные пространства автоматически удаляются после 24 часов неактивности.

## Безопасность и ограничения данных

- Проверка владельца Workspace и активной ролевой сессии.
- Проверка разрешений на уровне application/domain layer.
- Изоляция заказов и тикетов между Workspace.
- Внутренние заметки недоступны клиентской роли.
- Ограничение частоты действий.
- Проверка типов и размеров вложений.
- Лимиты вложений на уровне тикета и Workspace.
- Секреты хранятся в переменных окружения.
- Пользовательские сообщения не включаются в диагностические логи.
- Время хранения демонстрационных данных ограничено TTL.

## Архитектура

Проект разделён на несколько слоёв:

- `bot` — Telegram handlers, keyboards, middlewares и FSM.
- `application` — use cases и сценарии приложения.
- `domain` — сущности, бизнес-правила, статусы и проверки доступа.
- `infrastructure` — PostgreSQL, Redis, repositories и интеграции.

Telegram handlers не содержат SQL-запросов и не являются источником бизнес-правил.

Архитектура позволяет в дальнейшем подключить HTTP API и Telegram Mini App без дублирования бизнес-логики.

## Запуск

Требования: Docker Engine с Compose plugin и токен бота от [@BotFather](https://t.me/BotFather).

```bash
git clone https://github.com/Cardinal87/helpdesk-demo.git
cd helpdesk-demo

cp .env.example .env
```

Укажите `BOT_TOKEN` в `.env`, затем выполните:

```bash
docker compose up --build
```

При запуске применяются миграции Alembic и запускается Telegram long polling.

PostgreSQL и Redis используют именованные Docker volumes.

Остановка:

```bash
docker compose down
```

Полная очистка локальных данных:

```bash
docker compose down -v
```
